# CityMETER Transit — owner preferences

Carried from the Luxury Brands demo (owner, 2026-10-22) and set for Transit on 2026-10-31 (release 0.1). Read `PRODUCT_STATEMENT.md` and `DATA_METHOD.md` before changing what the first screen argues or how a number is counted.

- Apply LDS 0.9.7 (v0.9.7-owner.1, standalone-0.9.7-r1, color-srgb-10) and keep the map-first CityMETER layout (header 48 px, full map, right panel, collapsible chart tray, mobile bottom sheet). UI colours come only from `assets/theme.css`; data scales only from the exact 41-sample LUTs in `js/scales.js` (`count`, `activity`), the same HEX in light and dark. Never approximate a value by eye.
- Rail first (owner 2026-10-31: "แสดงแนวเส้นทางด้วย เน้นระบบราง ส่วนรถเมล์เป็น optional"): rail alignments, stations and interchanges are the subject; bus and boat are optional context layers, off by default, lazy-loaded, drawn in one quiet token with width (not colour) as the cue.
- Grain is a contract: one station record = one station–line (`17_RAIL_CATALOG`) or one station–project (`23_CONSTRUCTION_STATIONS`). Never merge records across lines — every relation in `31_INTERCHANGES` says `physical_entity_merge = FALSE`. A complex (จุดเปลี่ยนสาย) is a presentation group of records joined by current relations; pins and 3D plates may show it once, counts never collapse it.
- Status is never upgraded: operator roster listed → เปิดให้บริการ (a published list, not live operation); project membership → กำลังก่อสร้าง; existing/junction members of a project → ยังยืนยันไม่ได้ (never read as closed). Target dates are targets. Project-level progress is not station progress.
- Aha first, in 3D: the first paint frames the top interchange complexes (lines joined, then reach) with the city preset; the panel shows the count of จุดเปลี่ยนสาย, the lines and the hubs, then immediate actions (ดูทั้งหมด, เปรียบเทียบสาย). No onboarding gate. Snapshot numbers live in tests, never in UI constants.
- 3D style follows the pmndrs raycast-cycling example inside one MapLibre custom layer (`js/scene.js`): translucent white solids, a soft baked shadow, hover pulse, raycast cycling of stacked objects with the status dots. Data never hides behind basemap massing (depth is cleared before the scene). Camera presets never move or scale data; keep every 3D preset at pitch ≤ 90° − fov/2 − 3°.
- Elevation, station buildings and line colours come from the owner-approved OpenStreetMap download through `scripts/osm_enrich.py`, each with its OSM reference. Without a match an alignment's elevation is unknown (null), never a default. Building heights without OSM height tags are labelled display defaults.
- Line colours are third-party identity (the colour in the line's own name). Until the owner approves this exception to the LDS categorical palette, keep it reported in `DATA_METHOD.md` §7; while no sourced HEX exists use the declared LDS series fallback (`colorToken`) and say so.
- Ridership: one comparable series per chart (metric + unit + period + aggregation); never add arrivals to departures or ARL to BTS; a value the source reports for a whole station (Siam 2564) is shown once. Missing is never zero.
- Keep generic caveats and research-workflow residue out of ordinary UI; keep provenance short and factual (period · source link · coordinate role). Methodology lives in `DATA_METHOD.md` and help.
- Publication: no Google Drive/Docs links, local paths or credentials in any published file (`scripts/build-data.py` guard + `tests/data.test.js`). Work on `release/*`; `main` only after the release gate; verify the live URL (`npm run verify:live`) before saying a release is done.
- Breadcrumb is ประเทศไทย › จังหวัด › สาย › สถานี with the production province codes; a line crumb appears only when the station was reached through that line.
- No decorative brackets or coloured left rails on menus, tabs, cards or callouts; keep visible keyboard focus. Review real Thai and English at narrow and desktop widths in light and dark themes before claiming a change is done.
