# CityMETER Transit — owner preferences

Carried from the Luxury Brands demo (owner, 2026-10-22) and set for Transit on 2026-10-31 (release 0.1). Read `PRODUCT_STATEMENT.md` and `DATA_METHOD.md` before changing what the first screen argues or how a number is counted.

- Apply LDS 0.9.7 (v0.9.7-owner.1, standalone-0.9.7-r1, color-srgb-10) and keep the map-first CityMETER layout (header 48 px, full map, right panel, collapsible chart tray, mobile bottom sheet). UI colours come only from `assets/theme.css`; data scales only from the exact 41-sample LUTs in `js/scales.js` (`count`, `activity`), the same HEX in light and dark. Never approximate a value by eye.
- Rail first (owner 2026-10-31: "แสดงแนวเส้นทางด้วย เน้นระบบราง ส่วนรถเมล์เป็น optional"): rail alignments, stations and interchanges are the subject. Every other mode of the research master with coordinates stays available (owner 2026-10-31: "สายรถเมล วินมอไซค์ บขส หายไป … mode อื่นๆหายไป แก้ด้วย"): bus routes + BRT, bus stops, motorcycle-taxi stands, boats, intercity bus terminals and บขส. stops, conventional rail stops, airports — optional layers in the "ขนส่งอื่น" menu, off by default, lazy-loaded, quiet map-role tokens with a distinct shape per mode (never a categorical palette), route lines above the road casing and below the rail lines. The toggles themselves are always in sight (owner 2026-11-01: "หาปุ่มเปิดดู mode อื่นไม่เจอ"): one row "ขนส่งอื่น" under the toolbar on every screen with a toggle per mode (symbol + short name, ✓ when on); the row's label opens the counts and sources. Once switched on, a layer is visible at every zoom and on every screen (owner 2026-10-31: "แม้ไม่ใช่ default … ก็น่าจะเปิดดูได้ตลอดๆทุกๆหน้าจอ"): no minimum zoom (symbols shrink when far out), icons never depend on the label font. The station panel lists the other modes within 500 m (straight line from the station reference point); a layer that does not cover the station says "นอกขอบเขตข้อมูล", never zero.
- Grain is a contract: one station record = one station–line (`17_RAIL_CATALOG`) or one station–project (`23_CONSTRUCTION_STATIONS`). Never merge records across lines — every relation in `31_INTERCHANGES` says `physical_entity_merge = FALSE`. A complex (จุดเปลี่ยนสาย) is a presentation group of records joined by current relations; pins and 3D plates may show it once, counts never collapse it.
- Status is never upgraded: operator roster listed → เปิดให้บริการ (a published list, not live operation); project membership → กำลังก่อสร้าง; existing/junction members of a project → ยังยืนยันไม่ได้ (never read as closed). Target dates are targets. Project-level progress is not station progress.
- One station, one 3D form (owner 2026-11-01: the plate at the reference point beside the OSM hall read as a duplicate): when OSM maps the station's hall, the hall is drawn and the pin sits on it — no plate; otherwise the striped plate at the reference point. The panel keeps the reference coordinate and states the distance to the drawn hall when it is 20 m or more.
- Station level: a click on a station — panel, pin or 3D object — fits the station area (the focus-massing ring of `STATION_RADIUS_M` with the roofs of the buildings in it) to the visible map: below the toolbar, above the chart tray or the mobile sheet (owner 2026-10-31: "คลิกที่สถานี ควรจะ zoom to fit … รวมอาคารสามมิติ เต็ม viewport พอดี"). If the massing loads taller roofs than the frame allowed, refit once — unless the user has moved the camera.
- Aha first, in 3D: the first paint frames the top interchange complexes (lines joined, then reach) with the city preset; the panel shows the count of จุดเปลี่ยนสาย, the lines and the hubs, then immediate actions (ดูทั้งหมด, เปรียบเทียบสาย). No onboarding gate. Snapshot numbers live in tests, never in UI constants.
- 3D style follows the pmndrs raycast-cycling example inside one MapLibre custom layer (`js/scene.js`): translucent white solids, a soft baked shadow, hover pulse, raycast cycling of stacked objects with the status dots. Data never hides behind basemap massing (depth is cleared before the scene). Camera presets never move or scale data; keep every 3D preset at pitch ≤ 90° − fov/2 − 3°.
- Elevation, station buildings and line colours come from the owner-approved OpenStreetMap download (sha256 1cdb65b8…3de9fd67) through `scripts/osm_enrich.py` — or, when the raw file is not in the build environment, through `scripts/osm-browser-extract.js` run where the file is and `sources/osm/osm-derived-*.json` (`--osm-derived`), verified by sha256 of the raw file, of the function source and of the result. Each value keeps its OSM reference. Without a match an alignment's elevation is unknown (null), never a default. Building heights without OSM height tags are labelled display defaults. OSM-derived data is ODbL 1.0 with © OpenStreetMap contributors.
- Line colours are third-party identity (the colour in the line's own name), approved by the owner 2026-10-31 as an exception to the LDS categorical palette (`DATA_METHOD.md` §7): OSM route-relation `colour` first, the line family's colour for an extension, else the declared LDS series fallback (`colorToken`), each with its basis. Construction lines are dashed in 2D and in 3D.
- Ridership: one comparable series per chart (metric + unit + period + aggregation); never add arrivals to departures or ARL to BTS; a value the source reports for a whole station (Siam 2564) is shown once. Missing is never zero.
- Keep generic caveats and research-workflow residue out of ordinary UI; keep provenance short and factual (period · source link · coordinate role). Methodology lives in `DATA_METHOD.md` and help.
- Publication: no Google Drive/Docs links, local paths or credentials in any published file (`scripts/build-data.py` guard + `tests/data.test.js`). Work on `release/*`; `main` only after the release gate; verify the live URL (`npm run verify:live`) before saying a release is done.
- Breadcrumb is ประเทศไทย › จังหวัด › สาย › สถานี with the production province codes; a line crumb appears only when the station was reached through that line.
- No decorative brackets or coloured left rails on menus, tabs, cards or callouts; keep visible keyboard focus. Review real Thai and English at narrow and desktop widths in light and dark themes before claiming a change is done.

## Search — names found the way people type them (owner 2026-11-12)

- Since release 0.4.0 (citymeter-shell 0.7.0; owner 2026-11-12 12:05, VERBATIM: “ศึกษาแนวคิดเรื่อง Fuzzy search แล้ว implement กับ demo web ให้ได้ user benefit สูงสุดตาม user intent ในขณะนั้น และตาม product statement”; 13:15 “รวม university ไว้ด้วยกันเลย”) the search box lists names instead of filtering while it is typed in. `js/shell/fuzzy.js` is the matcher — the method of the CityMETER area-search brief (02-CityMETER__fuzzy-search-tech-brief v1, 19 Oct 2026, revised 20 Oct), moved from PostgreSQL to the browser because a demo is a static site: a name as typed, without its tone marks, by letters that sound alike, with its lead word (จ. อ. เขต) or the place it is in, typed on the other keyboard layout, or one or two keys off; the last three are guesses, made only when the sure steps find little. `js/shell/search.js` is the list under the box (a WAI-ARIA combobox in the flow of the panel) and `js/find.js` gives it this demo's names: the provinces that have a station, lines (by their name, short name, colour, source name and English name), systems of several lines, and stations of every status (a station also by its code, “N24”, and with its line, “สยาม สีลม”).
- Intent decides the action: a province opens its stations, a line its stations in order, a system its filter, a station its page. Enter with nothing chosen applies the words as the text filter, as the box always did; when the words keep no row, Enter marks the first name found as typed and Enter again opens it — a row is never opened unmarked. The map and the panel do not change while the reader types.
- What is chosen is shown. A filter or words chosen from the list apply to the whole page: the place being looked at is left (the province stays — a province without the brand is a reading of that province) and the other filters that would leave the choice no row are lifted first, the fewest that do (`makeWay` → `filtersToLift`, js/shell/search.js). An item chosen always opens: the filters it does not pass are lifted (`makeWayFor` → `filtersAgainst`). The `filters` option of `installSearch` (js/app.js) names the filters that may be lifted — never a counting unit or a measure. The number on the list's last row is the rows the words keep with the filters that are on — or, when those leave them no row, with the ones that stay once the fewest are lifted, as choosing the row does (`rowsAfterWay`).
- A guess is never chosen for the reader (the brief's decision of 10 Oct 2026: “เลือกแถวให้อัตโนมัติเฉพาะเมื่อมีพื้นที่เดียวที่ชื่อตรง”). Only an entry that alone is written with the very name typed, or that name with its place, is marked ahead — never a station that shares its name with another, and never an entry that only goes by the name once its head word is left out (“ภูเก็ต” is the province; เทศบาลนครภูเก็ต is found by it and is a row below).
- A row says what an entry is and where, in words: no number and no caveat. How sure a match is stands in words too — the tag “สะกดต่างจากที่พิมพ์”, the heading “ชื่อใกล้เคียง”.
- Nothing typed is stored or sent: no query log and no feedback button (the brief keeps both for after its PDPA review).
- Other names of a place are the four of `PROVINCE_AKA` (js/shell/fuzzy.js) and a district's name without เมือง. Who keeps a fuller alias list is an open decision of the brief: do not grow the list by hand. A name the data carries in one language is found in that language only.
- A new kind of entry needs its line in `searchNote` (js/find.js), its action in `openFound` (js/app.js); `tests/find.test.js` checks them. The demo's own `#search` input stays the field of the applied text filter (hidden, read by the code as before); if js/shell/search.js does not load, the box filters as it always did.
- On a phone, while a name is typed the panel stands tall and the box comes to its top, so the list has room above the keyboard (`html.find-typing` in navigation.css, set by js/shell/search.js while the box has the focus).
- Before a release, type in the box at 393 px and on a desktop: a name as written, one without its tone marks, one with a wrong key, one on the other keyboard layout, a text that is no name — and, with a filter on, a name of another kind (the filter gives way). A station is a level of this page, so one that alone is written with the name is marked ahead; two stations of one name are not. A line runs where it runs: for a line or a system the province filter is lifted too when it would leave no station (`context: []` in the `filters` option), and the status goes back to its default, never further. The line being looked at is left for a filter or words, and for a station that is not on it.
